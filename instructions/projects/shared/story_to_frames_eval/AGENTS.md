# Story-to-Frames project guidance

## Project wiki maintenance

Use the research-knowledge-map skill for the OKF wiki at `docs/wiki/`. Before substantive project work, read `docs/wiki/index.md`, relevant contribution pages, and the original governing sources. The wiki is navigation and synthesis, not execution authority.

Before finishing work that changes durable project knowledge, update affected pages with source-backed decisions, completed results, limitations and unresolved questions; update relevant indexes and the change log. Routine scoped upkeep is authorized. Routine questions/trivial edits need no wiki change. Unrelated bulk ingestion, broad refreshes, remote operations, experiment execution, authentication changes and background/CBM indexing are not authorized by this rule.

Preserve personal annotations, signed/hash-bound sources, contradictory evidence and historical decisions. Keep secrets out and use approved private retrieval references for restricted operations. State what was actually verified and when; model authorship is not human verification.

These files may be shared through NFS. Use one coordinating writer for shared indexes/overlapping pages. Other lanes should contribute under a unique `docs/wiki/contributions/<team>-<date>-<task-id>/` path until deliberately consolidated. Check existing changes before editing, never overwrite another task's work, and preserve source scope.

In the final handoff, name updated pages, source coverage and any deferred consolidation. If the skill/wiki is unavailable, disclose that and save a bounded handoff rather than claiming successful upkeep.


## Shared Skill Routing

For shared skill selection, explicitly read the parent [research workspace guidance](../../../AGENTS.md), including its Task-Based Skill Selection section, and check the current session catalog. Select only the narrowest applicable skill and name it in any subagent brief. These routes supplement this Story-to-Frames project's instructions; existing wiki ownership, contribution paths and execution boundaries remain authoritative.
